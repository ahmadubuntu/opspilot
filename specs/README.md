# OpsPilot Specification Guide

Specifications describe behavior.

They never describe implementation details.

Each specification should answer:

- Why does this feature exist?
- What problem does it solve?
- What are its responsibilities?
- What are its non-responsibilities?
- What are the inputs?
- What are the outputs?
- What errors can occur?
- What security constraints exist?
- What future extensions are expected?

A feature is considered ready for implementation only after its specification is reviewed.

Specifications are versioned.

Behavior changes require updating the specification first.
